# คู่มืออธิบายโค้ด – ครามสเตย์ สกลนคร (ระบบจองห้องพัก)

เอกสารนี้อธิบายว่าแต่ละไฟล์/แต่ละฟังก์ชันทำอะไร และถ้าอยากแก้ไขเรื่องไหน ต้องแก้ที่ไหน แล้วอะไรจะได้รับผลกระทบบ้าง

---

## 1. ภาพรวมการทำงาน

```
เบราว์เซอร์ (index.html + css + js)         Apache + PHP (XAMPP)           MySQL (sakon_booking)
┌──────────────────────────────┐   GET    ┌────────────────────┐  SELECT  ┌──────────────┐
│ js/app.js                    │ ───────► │ api/get_data.php   │ ───────► │ ตารางทั้งหมด │
│  เก็บข้อมูลทั้งหมดในตัวแปร DB │ ◄─────── │ (ประกอบเป็น JSON)  │ ◄─────── │              │
│  ผู้ใช้กดอะไร → แก้ DB → save()│  POST    ├────────────────────┤  DELETE  │              │
│                              │ ───────► │ api/save_data.php  │  +INSERT │              │
└──────────────────────────────┘          │ (เขียนทับทั้งก้อน) │ ───────► └──────────────┘
                                          └────────────────────┘
                                          api/config.php = ข้อมูลเชื่อมต่อ DB (ใช้ร่วมกัน)
```

**หลักคิดสำคัญ (ต้องเข้าใจก่อนแก้โค้ด):**

1. หน้าเว็บเป็น **Single Page App** ใช้ `#/...` ใน URL สลับหน้า (ไม่โหลดหน้าใหม่)
2. ตอนเปิดหน้า/เปลี่ยนหน้า `get_data.php` จะอ่านข้อมูล **ทั้งฐานข้อมูล** ส่งมาเป็น JSON ก้อนเดียว เก็บในตัวแปร `DB`
3. ทุกครั้งที่ผู้ใช้ทำอะไร (จอง, จ่ายเงิน, รีวิว ฯลฯ) โค้ดจะ **แก้ตัวแปร `DB` ในเบราว์เซอร์** แล้วเรียก `save()`
4. `save()` ส่ง `DB` **ทั้งก้อน** ไปให้ `save_data.php` ซึ่ง **ลบข้อมูลเก่าทุกตารางแล้ว INSERT ใหม่ทั้งหมด** ภายใน transaction เดียว
5. แต่ละแถวมี `public_id` (เช่น `U-abc123`, `B-xyz789`) เป็น id ฝั่งเว็บ ส่วน id ตัวเลขใน MySQL (AUTO_INCREMENT) เป็นของฐานข้อมูล ทั้งสองฝั่งเชื่อมกันด้วย `public_id`

> ผลของข้อ 4: ถ้าเพิ่ม **ฟิลด์ใหม่** ต้องแก้ครบ 3 ที่เสมอ คือ ตาราง SQL → `get_data.php` (อ่านออก) → `save_data.php` (เขียนเข้า) ถ้าลืมที่ใดที่หนึ่ง ข้อมูลฟิลด์นั้น **จะหายไปทุกครั้งที่บันทึก**

## 3. ฐานข้อมูล (sql/sakon_stay_xampp.sql)

| ตาราง | เก็บอะไร | ฟิลด์ฝั่งเว็บที่ตรงกัน |
|---|---|---|
| `User` | ผู้จอง (guest) | `users` ที่ role = guest |
| `Property_Owner` | เจ้าของที่พัก | `users` ที่ role = owner |
| `Admin` | ผู้ดูแลระบบ | `users` ที่ role = admin |
| `Accommodation` | ที่พัก (โรงแรม/อพาร์ทเม้น/หอพัก/รีสอร์ท) | `properties` |
| `Room` | ประเภทห้องของแต่ละที่พัก | `rooms` |
| `Booking` | การจอง + สถานะชำระเงิน + สลิป | `bookings` |
| `Review` | รีวิวดาว 1–5 | `reviews` |
| `News` | ข่าว/โปรโมชั่น/ประกาศ | `news` |
| `Site_Setting` | ชื่อเว็บ, ข้อความหน้าแรก, เบอร์, อีเมล | `site` |

**ข้อจำกัดที่ฝังอยู่ใน SQL (แก้ที่นี่ถ้าอยากเปลี่ยนกฎ):**
- ประเภทที่พักถูกล็อกด้วย `ENUM('โรงแรม','อพาร์ทเม้น','หอพัก','รีสอร์ท')` และอำเภอถูกล็อกด้วย `CHECK (district = 'เมืองสกลนคร')`
- รหัสผ่านยาวสูงสุด 20 ตัวอักษร (`VARCHAR(20)`) และ **เก็บเป็นข้อความธรรมดา ไม่เข้ารหัส**
- `Booking.pay_method` มีแค่ `'QR code'`

## 4. api/config.php

ทำ 3 อย่าง:
1. **ตั้งค่า DB** `$DB_HOST / $DB_NAME / $DB_USER / $DB_PASS / $DB_PORT` ถ้าตั้งรหัสผ่าน root ให้แก้ `$DB_PASS`
2. **ส่ง header JSON + CORS** และตอบ `OPTIONS` ทันที
3. **ปรับสคีมาอัตโนมัติ** ทุกครั้งที่ถูกเรียก: เพิ่มคอลัมน์ที่ขาด (`promptpay_id`, `rating_avg`, `review_count`, `room_available`), เปลี่ยนคอลัมน์รูป/สลิปเป็น `MEDIUMTEXT`, สร้างตาราง `Site_Setting`

ตัวแปร `$pdo` ที่สร้างไว้ถูกใช้ต่อใน `get_data.php` และ `save_data.php` (ตั้งโหมด error เป็น exception)

**ถ้าจะแก้:** เปลี่ยนชื่อฐานข้อมูล → แก้ `$DB_NAME` (และชื่อใน SQL ให้ตรงกัน)

## 5. api/get_data.php (อ่านข้อมูล)

- สร้างอาร์เรย์ `$out` ที่มีคีย์ `site, districts, types, users, properties, rooms, bookings, reviews, news, resets`
- `jarr()` แปลงข้อความ JSON ในคอลัมน์ (amenities, photos) เป็นอาร์เรย์
- ดึงตารางทีละตาราง แล้ว **แปลง id ตัวเลขเป็น `public_id`** (ใช้แผนที่ `$ownerPub`, `$accPub`, `$userPub`, `$roomPub`, `$bookingPub`)
- `$statusMapOut` แปลงสถานะ DB (`Pending`, `CheckedIn`...) → ตัวพิมพ์เล็กที่ JS ใช้ (`pending`, `checkedin`...)
- ค่าเริ่มต้นของ `site` อยู่ในโค้ดนี้ แล้วถูกทับด้วยค่าจาก `Site_Setting`

**ถ้าจะแก้:**
| ต้องการ | แก้ที่ | ผลที่ตามมา |
|---|---|---|
| ข้อความเริ่มต้นของเว็บ (ก่อนแอดมินแก้) | `$out['site']` | มีผลเฉพาะตอนยังไม่มีค่าใน `Site_Setting` |
| เพิ่มประเภทที่พัก | `$out['types']` + `PROP_TYPES` ใน `app.js` + `ENUM` ใน SQL | ต้องแก้ครบ 3 ที่ ไม่งั้นบันทึกไม่ได้/ไม่แสดง |
| ส่งฟิลด์ใหม่ไปหน้าเว็บ | เพิ่มคีย์ใน array ของตารางนั้น | ต้องเพิ่มใน `save_data.php` ด้วย |

## 6. api/save_data.php (เขียนข้อมูล)

ลำดับการทำงาน (ทั้งหมดอยู่ใน transaction เดียว ถ้าพลาดจะ rollback):

1. อ่าน JSON จาก body ถ้าไม่ใช่ JSON ตอบ 400
2. `beginTransaction()`
3. **DELETE ทุกตาราง** ตามลำดับที่ไม่ชนกับ Foreign Key (Review → Booking → Room → Accommodation → News แล้วจึง User/Owner/Admin)
4. INSERT `users` แยกตาม role ไปตาราง Admin / Property_Owner / User และเก็บ `$ownerMap`, `$userMap` (public_id → id ตัวเลข)
5. INSERT `properties` → `$accMap` (ข้ามถ้าหาเจ้าของไม่เจอ)
6. INSERT `rooms` → `$roomMap`
7. อัปเดตราคาเริ่มต้นที่พัก = ราคาห้องถูกสุด
8. INSERT `bookings` (แปลงสถานะกลับเป็นรูปแบบ DB ด้วย `$statusMapIn`)
9. INSERT `reviews` (บังคับดาว 1–5 ด้วย `max(1, min(5, ...))`)
10. INSERT `news`
11. `REPLACE INTO Site_Setting` สำหรับ `name, heroTitle, phone, email, about`
12. คำนวณ `rating_avg`, `review_count` ของที่พัก
13. คำนวณ `room_available` (ห้องคงเหลือ) ของห้อง
14. `commit()`

**จุดที่เพิ่งแก้ (สาเหตุ error “There is no active transaction”):**
เดิมมีคำสั่ง `ALTER TABLE ... AUTO_INCREMENT = 1` อยู่ในขั้นที่ 3 แต่ใน MySQL คำสั่ง `ALTER` (DDL) จะ commit transaction ให้ทันที ทำให้ `commit()` ตอนท้ายไม่มี transaction ให้ปิด **ห้ามใส่ `ALTER`, `CREATE`, `DROP`, `TRUNCATE` ภายใน transaction**

**ถ้าจะแก้:**
| ต้องการ | แก้ที่ | ผลที่ตามมา |
|---|---|---|
| เพิ่มฟิลด์ในตารางใด | แก้ `INSERT` ของตารางนั้น (ทั้งรายชื่อคอลัมน์, จำนวน `?`, และ array ใน `execute`) | ต้องมีคอลัมน์ใน SQL และอ่านออกใน `get_data.php` |
| เปลี่ยนสูตรห้องคงเหลือ | ขั้นที่ 13 (`GREATEST(0, room_count - ...)`) และฟังก์ชัน `takesRoom/booked/freeQty` ใน `app.js` | ต้องแก้ให้ตรงกัน 2 ฝั่ง ไม่งั้นตัวเลขหน้าเว็บกับ DB ไม่ตรงกัน |
| เพิ่มคีย์ข้อมูลหน้าเว็บ (site) | รายการ `['name','heroTitle',...]` ขั้นที่ 11 | ต้องเพิ่มใน `$out['site']` ของ `get_data.php` และหน้า `adminSite()` |

## 7. js/app.js (ไฟล์หลัก 1,077 บรรทัด)

### 7.1 ตัวช่วยทั่วไป (บรรทัด ~1–40)
| ชื่อ | ทำอะไร |
|---|---|
| `B(n)` | จัดรูปแบบตัวเลขแบบไทย เช่น `1,200` |
| `esc(s)` | ป้องกัน XSS แปลงอักขระพิเศษ HTML **ต้องใช้ทุกครั้งที่แสดงข้อความที่ผู้ใช้พิมพ์** |
| `uid(prefix)` | สร้าง `public_id` สุ่ม เช่น `B-k3j9a2` |
| `today()`, `addDays()`, `nights()`, `thDate()` | จัดการวันที่/จำนวนคืน/แสดงวันที่ไทย |
| `photo(seed,label)` | วาดรูปจำลองเป็น SVG เมื่อที่พัก/ห้องไม่มีรูป |
| `qrSVG`, `maskPP` | วาด QR / ปิดบังเลขพร้อมเพย์ (เช่น `081xxxx789`) |

### 7.2 ค่าคงที่ที่ปรับแต่งได้
| ค่า | ความหมาย | ถ้าแก้ |
|---|---|---|
| `DISTRICT` | อำเภอเดียวที่เปิดบริการ | หน้าเว็บกรองที่พักตามค่านี้ ต้องแก้ SQL (`CHECK`) และ `save_data.php` ที่ใช้ `'เมืองสกลนคร'` เป็นค่าเริ่มต้นด้วย |
| `PROP_TYPES` | ประเภทที่พัก | ดูตารางในหัวข้อ 5 |
| `AMENITIES` | รายการสิ่งอำนวยความสะดวกให้ติ๊กเลือก | แก้ได้อิสระ (เก็บเป็น JSON ใน DB) |
| `ST`, `PS`, `RS` | ชื่อไทย+สีป้ายของสถานะการจอง / การชำระ / ห้อง | แก้ข้อความป้ายได้ แต่ **ห้ามเปลี่ยนคีย์** (`pending`, `paid`...) เพราะผูกกับ ENUM ใน SQL |
| `DB_KEY`, `SESSION_KEY` | ชื่อคีย์ใน localStorage (เก็บแค่ session ล็อกอิน) | เปลี่ยนแล้วทุกคนต้องล็อกอินใหม่ |

### 7.3 ชั้นข้อมูลและการเชื่อม API
| ฟังก์ชัน | ทำอะไร |
|---|---|
| `fetchSeed()` | GET `api/get_data.php` |
| `load()` | ตั้ง `DB` จากข้อมูลที่ดึงมา + อ่าน session จาก localStorage |
| `save()` | POST `DB` ทั้งก้อนไป `save_data.php` โดย **ต่อคิว** (`savePromise`) ไม่ให้บันทึกซ้อนกัน ถ้า error จะขึ้น toast สีแดง (ข้อความในรูปที่คุณเจอมาจากตรงนี้) |
| `refreshData()` | รอ save ที่ค้างให้เสร็จ แล้วดึงข้อมูลล่าสุดใหม่ |
| `setSession()`, `me()` | จัดการผู้ใช้ที่ล็อกอินอยู่ |
| `api.*` | `login`, `register`, `resetPassword`, `confirmReset`, `properties` (ค้นหา/กรอง), `book` |

> ข้อควรระวัง: `save()` ส่งข้อมูลจาก **เบราว์เซอร์ของผู้ใช้คนนั้น** ไปเขียนทับทั้งฐานข้อมูล ถ้าสองคนใช้พร้อมกัน คนที่บันทึกทีหลังอาจทับข้อมูลของอีกคน (เป็นข้อจำกัดของดีไซน์แบบต้นแบบ)

### 7.4 กฎห้องว่าง/การจอง
| ฟังก์ชัน | ความหมาย |
|---|---|
| `takesRoom(b)` | การจองนี้ “กินห้อง” หรือไม่: สถานะยังใช้งาน **และ** จ่ายแล้ว/รอตรวจสลิป **และ** ยังไม่เลยวันเช็กเอาต์ |
| `booked(rid)` | จำนวนห้องที่ถูกกินแล้วของห้องประเภทนั้น |
| `freeQty(rid)` | ห้องว่าง = จำนวนห้อง − `booked` (0 ถ้าสถานะห้องไม่ใช่ available) |
| `canHold(b)` | ตรวจว่าห้องยังพอให้ล็อกการจองนี้ไหม (ใช้ตอนอัปโหลดสลิป) |

| `ownerBookings` / `setBookingStatus` | | เจ้าของ: ดูการจองและเปลี่ยนสถานะ |
| `ownerPays` / `setPay` | | เจ้าของ: ตรวจสลิป `paid` → การจองเปลี่ยนเป็น `confirmed` อัตโนมัติ / `rejected` → คืนห้อง |
| `viewAdmin` + `adminReview` / `reviewProp` | `#/admin` | แอดมิน: อนุมัติ/ปฏิเสธที่พัก |
| `adminNews` / `editNews` / `saveNews` / `toggleNews` / `delNews` | | แอดมิน: จัดการข่าว |

| `adminUsers` | | แอดมิน: ดูรายชื่อผู้ใช้ |

### 7.6 เราเตอร์และจุดเริ่มต้น
- `route()` อ่าน `location.hash` แยกหน้า เรียก `view*` ที่ตรงกัน และ **ดึงข้อมูลใหม่จาก DB ก่อนทุกครั้ง** สำหรับหน้าใน `LIVE_PAGES`
- `needLogin(role)` แสดงหน้า “ต้องเข้าสู่ระบบ” ถ้าสิทธิ์ไม่ถึง (เช็กในแต่ละ `view` ด้วย `session.role`)
- `init()` ดึงข้อมูลครั้งแรก ถ้าล้มเหลวจะแสดงหน้าแนะนำติดตั้ง XAMPP
- เพิ่มหน้าใหม่: เพิ่ม `else if(head==='ชื่อ') viewXxx();` ใน `route()` และเขียน `function viewXxx(){ app().innerHTML = ... }` (ถ้าต้องการข้อมูลสดให้เพิ่มชื่อใน `LIVE_PAGES`)

## 8. js/qr.js
| ฟังก์ชัน | ทำอะไร |
|---|---|
| `QR.build(text)` | สร้างเมทริกซ์ QR (โหมดไบต์, ECC ระดับ M, เวอร์ชัน 1–10, รองรับไม่เกิน ~213 ไบต์) |
| `QR.svg(text,label)` | แปลงเมทริกซ์เป็น SVG |
| `QR.promptPayPayload(id, amount)` | สร้างข้อความ QR พร้อมเพย์ตามมาตรฐาน EMVCo + CRC16; คืน `null` ถ้าเลขพร้อมเพย์ไม่ถูกต้อง |
| `QR.validPromptPayId(id)` | ตรวจรูปแบบ: เบอร์มือถือ 10 หลัก (ขึ้นต้น 0) / บัตรประชาชน-ภาษี 13 หลัก / e-Wallet 15 หลัก |
| `QR.crc16` | คำนวณ checksum |

**อย่าแก้** ส่วน Reed–Solomon / `build` เว้นแต่จำเป็น ถ้าแก้ผิด QR จะสแกนไม่ได้ ส่วนที่ปลอดภัยในการแก้คือแค่เรียกใช้ฟังก์ชันจาก `app.js`

## 10. สูตรแก้ไขที่พบบ่อย (Cheat Sheet)

| อยากทำ | ต้องแก้ที่ไหน (ตามลำดับ) |
|---|---|
| **เปลี่ยนสีธีม** | `css/style.css` ตัวแปรใน `:root` (และชุดโหมดมืด) |
| **เปลี่ยนชื่อเว็บ/เบอร์ติดต่อ** | ล็อกอินแอดมิน → แท็บ “ข้อมูลหน้าเว็บไซต์” (ไม่ต้องแก้โค้ด) |

## 11. ข้อควรระวัง / จุดอ่อนที่ควรรู้

1. **บันทึกแบบเขียนทับทั้งก้อน** — ผู้ใช้หลายคนพร้อมกันอาจทับข้อมูลกัน และข้อมูลที่ไม่ผ่านเงื่อนไข (เช่นการจองที่หาห้องไม่เจอ) จะถูกข้ามและหายไป
2. **รหัสผ่านเก็บแบบข้อความธรรมดา** และถูกส่งมายังเบราว์เซอร์ทุกคนผ่าน `get_data.php` (ผู้ใช้ที่เปิด DevTools จะเห็นรหัสของทุกคน) ใช้ได้เฉพาะเป็นต้นแบบ/ทดลอง
3. **สิทธิ์ตรวจที่ฝั่งเบราว์เซอร์เท่านั้น** — API ไม่ได้ตรวจว่าใครเป็นแอดมิน ใครส่ง POST มาก็เขียนทับได้
4. **รหัสรีเซ็ตรหัสผ่านแสดงบนหน้าจอ** ไม่ได้ส่งอีเมล
5. **ห้ามใช้คำสั่ง DDL ใน transaction** (`ALTER/CREATE/DROP/TRUNCATE`) ดังที่เกิด error ครั้งนี้
6. **ฟอนต์โหลดจาก Google Fonts** ถ้าออฟไลน์จะใช้ฟอนต์สำรองของเครื่อง

ถ้าจะนำไปใช้งานจริง ควรปรับข้อ 1–3 เป็นอันดับแรก (แยก API เป็นรายการ เช่น `book.php`, `login.php` และตรวจสิทธิ์ที่ฝั่ง PHP)
